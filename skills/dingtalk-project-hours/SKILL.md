# 钉钉项目工时获取

交付可追溯的项目工时明细及项目、人员汇总。以真实填报为依据，区分报表口径与审批状态，不把历史数字当成当前结果。

## 范围与入口

- 从请求及上下文确定项目、时间、人员和状态。用户说“全部工时”时，按这些项目的全部历史、所有可见人员获取；明确披露权限及未提交记录的覆盖限制。
- “四个项目”在 Miracle 的上下文中通常是国控 HCP360、云顶会议有效性分析、诺华 Swift AI、诺华 Baize 2.0。编码和实际系统名称见 [宜搭操作参考](references/yida-export.md)，查询时核对，不推广到其他公司。
- 优先使用已授权、能提供完整字段的 API/CLI；没有合适接口时使用当前可用浏览器工具。浏览器操作前按环境要求读取浏览器技能；不绑定某个工具名称、浏览器配置或私人登录凭证。登录失效时请用户恢复登录，再续做。
- 本技能仅查询、临时筛选、导出及本地整理；不修改工时、提交审批或保存共享筛选条件。

## 获取流程

1. 使用宜搭时先读 [宜搭操作参考](references/yida-export.md)。记录获取时间、项目编码、日期范围、人员范围、筛选状态及页面总条数。
2. 导出“工时明细报表”。全部历史须清除默认日期限制，核对选中项目和人员筛选；选择全部结果，不是当前页。
3. 检查“工时填报记录”的状态筛选。读取运行中记录，判断是否存在未进入报表的工时；用户仅要已审批时，必须取得明确审批证据，不能用报表名称代替。
4. 下载并读取真实文件。校验工作表、表头、日期及项目范围，区分父表单数与展开明细行数。下载超时先检查文件是否已生成，避免反复导出。
5. 规范化并对账，再汇总。具体父子表处理、状态转换及重叠检查见下述规则。

## 规范化与对账

- 每条明细保留：项目编码、系统项目名称、展示名称、人员（ID 若有）、工作日期、小时数、事项、描述、部门、实例 ID、子行 ID（若有）、原始审批结果/实例状态、来源类型、文件名、工作表、源行号、获取时间。
- 按实际表头解析，遇到必需字段缺失或无法解析的行，保留异常并列明影响，不默默丢弃。小时用十进制定点计算；保留原始精度。
- 父子表只前向填充父字段，遇到新实例必须重置；不填充子行日期、项目或工时。只累计子行工时，不叠加父表“合计工时”。
- 同一文件重复加载可按文件摘要识别。稳定实例＋子行 ID 可识别同一明细；源行号只在该文件内有效。没有稳定子行 ID 时，不能按项目＋姓名＋日期删除合法多条记录。
- 报表与运行中记录按项目编码、人员、日期检查重叠候选，再比较事项、小时、实例及导出时点。候选不是已证实重复；两次导出之间审批流转可能造成重叠。刷新受影响范围或查明实例归属后再合并。
- 无法调和的记录单列“待核验”，分别展示两源的工时小计，不给出可能重复的确定合计。仅将已确认未纳入报表的运行中工时追加。
- 报表未提供审批字段时，标为“报表口径／审批状态未提供”；运行中单列。拒绝、撤回、终止、草稿等若存在，单独披露，不默认为有效交付投入。
- 每人每日超过 24h、周工时集中一天、无日期或负数等标为异常，保留原始记录，不自动摊平或改写。缺费率不推算金额；小时转人天必须注明已确认的日工时标准。

## 输出与验收

默认提供 Excel；使用环境中可用的表格技能制作和核验，不要求上传云端。最少包含：

| 页签 | 内容 |
|---|---|
| 项目汇总 | 项目、日期跨度、人数、报表工时、确认未纳入报表的运行中工时、可合计数、待核验数与覆盖说明 |
| 人员投入 | 项目 × 人员，按相同口径分列工时，回答每个项目有哪些人、投入多少 |
| 工时明细 | 标准化逐行数据与追溯字段；不同来源、审批状态不混淆 |
| 口径与异常 | 获取时间、过滤条件、范围缺口、审批重叠、解析异常及费率缺口 |

交付前检查：明细按相同纳入口径汇总＝项目合计＝人员合计；状态小计可勾稽；每个所选项目均出现（零记录说明原因）；行数差异可解释；输出仅含目标项目。保留原始导出供本地追溯，不把其他项目数据混入交付件。

最终给出文件链接、项目小时数、数据截止时间、审批口径和未解决缺口。不能把“已导出”说成“全部准确”，也不能把工时说成已核定财务成本。

## 调用示例

“用 $dingtalk-project-hours 拉取国控 HCP360、云顶、Swift AI、Baize 2.0 的全部历史人员工时，包含审批中记录并核对是否重复，给我成本统计用 Excel。”
