## A. 统计报表 → 工时明细报表

1. 检查“工时日期”：曾默认最近 90 天；全部历史必须清空。确认填报人、部门没有仅本人或局部限制。
2. 在实际“项目”多选框逐一选项目。选择后下拉可能保持展开，点击下一个位置前先检查；否则容易误选额外项目。核对所有选中标签和编码，再搜索。
3. 记录过滤条件、结果条数、可见日期。页面分页不等于导出限制，确保导出全部匹配结果。
4. 报表卡片表头有导出图标。曾可见 SVG 引用 `#iconexport1`，仅用作寻找提示；从当前 DOM/可访问名称确认后操作。
5. 在“我的导出”中等待目标文件完成，核对生成时间和文件名再下载。有时下载的是带密码 ZIP；仅在本地使用界面给出的密码解压，不写入 Skill、日志或聊天。

曾观察的单行表头（字段顺序不应作为唯一解析依据）：

`部门、填报人、工时日期、工时、事项、项目编号、项目名称、项目经理、BDCode、商机名称`

- 日期可能是 `2026/10/16 00:00:00` 字符串，也可能为 Excel 日期；统一为工作日期但保留原值。
- 表中未提供审批状态、实例 ID。不要称作“已审批工时”。报表粒度也可能是聚合结果，不能强行和表单逐行一一关联。

## B. 工时管理 → 工时填报记录

1. 检查默认筛选：曾为“审批结果 包含 同意”，会隐藏运行中记录。
2. 临时改为“实例状态 包含 运行中”查询运行中。不要点击保存共享筛选；如需更多状态，分别查询并标记。
3. 曾有 `工时明细.项目名称` 旧字段为空；用它筛选可能错误返回 0。实际子表 `项目` 是关联字段。优先用真实关联字段筛选；若 UI 无法准确筛选，再在现有授权可见范围导出后按项目编码本地截取，排除无关项目。
4. “导出”选择“导出所有（共 N 条）”，非当前页。选择能保留项目关联、工时明细、审批结果、实例状态和实例 ID 的字段；曾默认仅 12/20 项，缺少必需字段时选择完整字段。
5. 等待“文件生成成功，点击下载”。工具超时不证明失败：先看当前页面及新下载文件，再决定是否重试。
6. 记录父表单总条数 N。一个表单有多条工时，展开导出行数大于 N 属正常；应对账唯一实例数和实际子表行数，不能强令相等。

## 子表导出结构

曾为工作表“数据”，前两行是父字段和子字段表头。下面仅为定位提示；每次验证实际表头和合并区域。

| 范围 | 已观察到的字段 |
|---|---|
| 父字段 | 提报人、合计工时（小时）、员工所在部门、提交人、创建时间、修改时间、审批结果、实例标题、提交人组织、实例ID、当前审批节点、实例状态 |
| 子字段（工时明细） | 工作日期、工时、事项、项目、商机、工作描述、工时所在部门、项目名称 |

父字段可能为合并单元格，只有首条子行带值。处理规则：

1. 新实例 ID 开始新的父上下文，不能承接上一实例的空父字段；同一实例续行仅继承父上下文。无法确定实例边界时停止计入并报告异常。
2. 子行保留独立项目、日期、工时、事项、描述。一个父表可含多个项目；先展开，再按项目编码过滤。
3. 实际“项目”字段可能形如 `系统名称-CP202607220207[FINST-…]`。提取完整 `CP` 加数字编码，按目标编码精确比对，不做客户名模糊匹配。
4. 旧“项目名称”可能全空；不要因此丢弃有真实关联项目的行。
5. “提报人”是工时归属人，“提交人”可能为代填人。保留两者，按提报人汇总；没有身份 ID 时注明姓名碰撞风险。
6. 父表“合计工时”仅作表单级辅助核验，不加入子行合计。目标项目过滤后子行和可能小于父表合计，这是正常跨项目表单。

## 合并与审批流转

- 报表与运行中导出尽量在同一查询窗口完成，保留各自获取时间。
- 报表 100h、运行中 12h，不能仅凭两张表名称断定合计 112h。先检查运行中是否已被报表覆盖。
- 项目＋人员＋日期相交时，只是候选重复：同日可有多个事项、不同记录。优先查明实例和审批转换；报表无实例 ID 时回到记录页核验或刷新范围。
- 查明某运行中明细已进入报表后只计一次；没有证据不能自动删行或强加。待核验时分别报来源小计及未调和项，不报确定的去重总量。
- 实例 ID 不等于子行 ID；同一实例两条相同工时仍可能合法。文件＋行号可追溯，但跨导出行号变化，不能作永久唯一键。

## 输出的数据边界

“全部”指已验证查询范围及当前账号可见的记录，不代表未填报工时。草稿、无权限项目、其他项目/商机编码、系统历史归档等未覆盖时明确说明。

工时可作为成本底稿，但缺少人员实际成本率、费率生效日期、税费或摊销口径时不计算货币成本。不用以往报价中的销售 rate 充当工资成本。
