# macOS / Windows 兼容性验证

## 场景与验收标准

这些是只读决策推演，核对 Skill 能否给出受支持的下一步，不操作真实报销单。

| 场景 | 原版缺口 | 修订后的预期决策 |
| --- | --- | --- |
| Windows 多个钉钉窗口 | 只有 Mac 应用标识，没有窗口分支 | 从清单核对标题和内容，使用精确窗口 ID；不取第一项，不用 Mac bundle ID |
| Windows 钉钉未打开 | 没有启动与刷新步骤 | 工具支持时从应用清单取 ID 启动、重新选择窗口；不猜 exe 路径 |
| Windows 中文带空格凭证路径 | 文件选择器无条件使用“前往文件夹” | 读取对话框，在地址栏或文件名字段输入可访问路径；核对文件名及数量 |
| Windows 坐标点击前做过 AX 观察 | 没有坐标映射失效规则 | 对绑定窗口重新截图后再定位，采用工具支持的滚动和输入参数 |
| WSL 文件交给 Windows 对话框 | 没有执行主机和路径边界 | 先确认同一凭证的 Windows 可访问路径，不直接提交 `/home/...` |
| 网页入口与桌面会话不同 | 无网页登录验证步骤 | 仅使用已指定或确认的入口，重新核对公司、表单及会话；使用浏览器支持的上传接口 |
| Windows 无 PDFKit、OFD 不可读 | PDFKit 仅提到 Mac，OFD 能力边界不清 | PDF 使用已有可用渲染器；OFD 核对同票据可读副本，否则待核，不猜金额 |
| 环境没有桌面或浏览器控制工具 | 降级说明仅在 README | 继续可独立完成的核对与可粘贴内容，明确未填单，不声称保存成功 |
| macOS 已登录钉钉 | 保留已有可用路径 | 按应用清单确认 bundle ID 并读取状态，原生对话框可用“前往文件夹” |
| 同一订单两份截图及一张替票 | 费用规则回归 | 实付87.50＋157.80＝245.30元，475.20元替票不累加；四张铁路票合计341.00元；再加220.00元星巴克，总计806.30元 |
| 保存／上传超时 | 保留原防重复规则 | 查看同一草稿和附件再决定重试，不因调用成功声称已保存，不重复创建 |

## 本次验证记录（2026-10-15）

PR 合入以远端 `d2b5266` 为基础，保留已有适用范围、多币种、实际／拟报销额、替票制度和通用性验证记录；没有用较旧的本地副本覆盖这些规则。

- 修改前核对本次起始的本地仓库副本和已安装文件：安装版绑定 Mac App ID 和特定工具；仓库版已泛化工具选择，但两份文件都无 Windows 文件选择器分支。上述平台场景存在指引缺口。
- 修改后逐条推演上表 11 个场景，平台参考覆盖对应下一步；原有费用去重、默认草稿、提交授权和结果读回规则保留。此项为人工静态推演，不是独立模型评测或 UI 自动化。
- 依据当前 `mcp__cua_repl` 返回的工具文档核对 Windows 窗口 ID、坐标映射及滚动约束；未假定所有 Agent 都提供此工具。
- macOS 实际只读检查：`cua.computer.target` 返回 `mac`；从应用清单确认钉钉后，用 `com.alibaba.DingTalkMac` 成功绑定并读到窗口状态。未填写、上传、保存或提交报销单。
- 仓库版与安装版均通过官方 `quick_validate.py`（`Skill is valid!`）及 UI 元数据 YAML 检查；所需 PyYAML 6.0.3 仅装到临时验证目录，未修改全局环境。
- 四份 Markdown 的相对文件链接与行尾空白检查通过；与修改前备份比较的 `git diff --no-index --check` 通过。两份 Skill 的完整文件清单及逐文件 SHA-256 一致，共 6 个文件。
- 将 README 中 macOS 安装命令的目标重定向到隔离的“中文 带空格”目录，连续执行两次，文件清单与源目录一致，没有嵌套同名目录；该检查验证复制命令，不覆盖所有用户环境变量配置。
- 当前主机没有 Windows 和 PowerShell；Windows 安装命令只做静态审查。Windows 的窗口启动、输入、中文路径上传、保存后重新打开仍需在具备相应工具的 Windows 环境实测。macOS 本次也未重新验证完整填单流程。

## 后续实机验收

使用获准的测试表单和合成凭证；记录系统、客户端、工具版本、目标表单及每步读回证据。验证应用／窗口定位、中文带空格路径、文本及金额读回、附件数量、草稿重开与中断后续填。提交测试需要明确的测试范围和提交授权，不以验证 Skill 为由提交真实费用。
