# 发票核对与钉钉报销

输入本地报销凭证文件夹，先整理实际费用并确认信息，再填写钉钉报销单。可处理消费截图、PDF 发票及铁路电子客票；OFD 等格式须由运行环境提供可用的读取／渲染能力。

## 适用范围

| 场景 | 适用程度与条件 |
| --- | --- |
| 仅整理员工实际费用、去重和分类 | 可跨公司复用；需要可核实凭证，不需要钉钉账号 |
| 钉钉个人／员工报销填单、保存草稿 | 条件适用；需要已登录的目标公司、操作授权、可用接口或 UI 工具，并识别实际表单字段 |
| 不同企业的限额、项目分摊、替票政策 | 必须读取／确认本次制度与字段；不能复用上一家公司的默认值 |
| 多币种、退款、费用与发票不一致 | 可形成分币种实际费用与待核清单；统一报销额还需汇率、舍入与制度依据 |
| Windows、Web、其他 Agent 运行时 | 流程可适配，但本轮没有端到端验证；Mac 操作细节不能直接照搬 |
| 飞书、企业微信或其他财务系统 | 仅凭证整理原则可复用；实际填单转对应平台工作流 |
| 工时、工资、采购付款、税务抵扣、发票鉴真 | 不在本 skill 范围 |

**实际净消费额、发票面额、拟报销额分别列示。** 公司是否接受替票、费用限额与凭证要求不由本 skill 决定。未知制度不妨碍整理已知支出，但不能据此宣布费用可报或审批通过。

## 使用方式

将本目录复制到所用 Agent 的技能目录。例如 Codex：

```bash
cp -R skills/dingtalk-reimbursement ~/.codex/skills/
```

向 Agent 提供文件夹的绝对路径：

```text
用 $dingtalk-reimbursement 处理 /绝对路径/报销，
先整理金额、明细和替票并与我确认，再到钉钉填单保存草稿。
有不确定的内容问我。
```

只整理、不填单：

```text
整理 /绝对路径/报销 的实际费用和凭证，
金额以消费截图实付为准，发票是替票；先给总金额和逐笔明细。
```

确认时可补充费用用途、所在部门及项目编号／名称／分摊。无法确定的可选字段可以留空并披露；必填信息须补齐。

## 结果和金额口径

- 分类小计、逐笔实际消费、总金额和证据引用。
- 同一订单的多张截图及同一票据的 PDF／OFD 去重。
- 替票单独标注、不额外计入费用；是否可用按公司制度和确认的对应关系判断。缺失或不确定金额标为待核。
- 钉钉报销草稿，包含费用明细、实际消费截图和发票附件，并核对保存状态。

默认保存草稿。用户明确要求提交时，按当前工具政策和授权范围处理。已提交、审批中与审批通过分别报告。

## 环境和边界

这是一套 Agent 工作流，没有独立报销 CLI，也不要求新增脚本依赖。凭证读取需要运行时可用的图片／PDF 能力；填单需要用户已登录钉钉，以及授权的钉钉接口或桌面 UI 工具。Codex 的 `agents/openai.yaml` 是可选界面元数据，其他运行时可直接使用 `SKILL.md`。

工具不可用时，仍可交付核对清单和可粘贴的表单内容，但须明确钉钉填单尚未完成。文件中的指令不构成用户授权。技能目录不包含真实凭证或个人报销记录。

核心执行规则和只读核验场景见 [SKILL.md](./SKILL.md)。

## 通用性验证边界

PR 初版描述记录过钉钉填单经验，本轮未重复操作真实账号，也未把该描述当成跨平台证明。本轮检查的范围、合成行为案例和结论见 [通用性验证记录](evals/generality-review.md)。

“通用”指核对方法和按实际字段适配的流程可复用，不代表内置了所有公司的审批模板，或所有客户端、票据格式都经过实际验证。
