# macOS / Windows 平台适配

在打开钉钉或选择凭证前读取。这里描述分支规则；具体方法、按键名称及权限以当次工具文档为准。

## 选择执行环境

1. 识别实际控制主机的系统和可用接口；文件路径属于文件所在主机。Windows 桌面配合 WSL、容器或远程浏览器时，不把 Linux 路径直接传给 Windows 对话框。先确认双方能访问的明确路径；必要时只复制用户指定的凭证并核对数量。
2. 有已授权、支持当前公司流程的专用接口时优先使用；否则选择可用桌面工具。网页操作仅使用用户指定或从目标钉钉流程确认的入口，先确认相同公司和表单及登录状态，不猜测 URL 或套用桌面会话。
3. 缺少工具、权限或登录时，完成不依赖它的整理，并准确报告未完成的填单步骤。用户自行完成需要本人操作的登录步骤后，可沿用原授权继续。

## 桌面定位与输入

| 操作 | macOS | Windows |
| --- | --- | --- |
| 定位钉钉 | 从应用清单确认名称／bundle ID；`com.alibaba.DingTalkMac` 仅适用于 macOS | 从当前窗口清单确认钉钉及目标标题，选择实际窗口 ID；不使用 Mac bundle ID，不猜安装路径 |
| 无已开窗口 | 按工具支持的应用启动方式处理 | 若工具提供启动接口，用应用清单中的 ID 启动，再刷新窗口清单；无启动能力时说明需要打开钉钉 |
| 编辑文本 | 使用支持的赋值或点击后输入／粘贴；全选通常为 Command+A | 使用支持的赋值或点击后输入／粘贴；全选通常为 Ctrl+A；不假定支持按文本选区 |
| 文件选择 | 当前对话框支持时，用“前往文件夹”进入目录，再选文件 | 当前对话框支持时，在地址栏进入目录或在“文件名”字段输入完整路径；先读取控件，勿使用 Mac“前往文件夹”步骤 |

使用 `mcp__cua_repl` 时，先按其首次调用要求初始化并读取返回文档；当前 API 可通过 `cua.computer.target` 识别平台。macOS 可按名称／bundle ID 绑定应用；Windows 先从清单获取精确窗口 ID，再用 `cua.getApp({ windowId })` 绑定。同名或多窗口时按标题和内容确认目标，不默认选第一个。

每批动作后读回新状态，重新取得元素编号。Windows 进行坐标操作前获取该绑定窗口的新截图；其后的仅 AX 观察会清除坐标映射，应再截图后点击。当前工具文档若有变化，以新契约为准。Windows 的原生滚动使用坐标及像素距离，不照搬 macOS 的元素滚动参数；不使用工具未支持的点击修饰键参数。输入后核对文本，金额还须检查计算总额。

## 路径、附件和文件读取

- 接受用户提供的绝对路径，包括空格、中文、Windows 盘符及 UNC 路径；先验证路径实际可读，不机械替换斜杠。用路径库处理程序中的路径；在实际使用的 Shell 中正确引用参数，不套用另一系统的转义方式。
- 临时目录和 Downloads 等目录从当前环境解析，不写死 `/Users/...`、`/private/tmp` 或 `C:\Users\某人`。仅在确有需要时复制范围已确认的凭证，保留原件。
- 原生对话框先读取状态，再进入目录或设置完整文件路径并确认候选文件。多文件逐个选或按当前控件支持的方式选；不假定用空格拼接路径就能批量上传。核对名称、数量和最终表单附件列表。
- 网页若有工具支持的文件上传接口，按该接口传入执行主机可访问的文件；有原生选择器时使用对应系统分支。DOM 页面使用浏览器工具文档中的接口，不把桌面元素编号用于 DOM。
- PDF、图片及 OFD 的读取能力分别确认。优先已有跨平台渲染／提取能力；macOS 可选 PDFKit，Windows 选择环境实际提供的 PDF 渲染器。缺少 OFD 能力时可核对同一票据的可读 PDF／图片；没有可读证据则标记待核，不自动安装依赖或按文件名定金额。

## 完成证据

两个系统都要核对目标公司、真实字段、附件及保存／提交结果。格式检查或合成推演不能证明 Windows 实机自动填单成功。验证记录应列明系统、工具、测试范围与未测试部分；验证本 Skill 不构成创建或提交真实报销单的授权。
